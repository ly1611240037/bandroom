## Context

遵循历史 booking-management 和前端规格。初始无缓存测试有三个预约用例因日期过期失败，前端构建通过。

## Goals / Non-Goals

目标：固化开发原则、修复可复现问题、通过无缓存测试与页面验证。
非目标：新业务、全仓格式化、框架迁移、改变老板权限。

## Decisions

- skill 保留原文、固定 commit，AGENTS.md 为规则入口。
- 预约服务内部时钟供测试固定时间，生产使用 time.Now。
- 一次加载当天预约区间，内存计算候选时段；提交仍事务校验。
- 营业与日期筛选按 UTC+8；SQLite 每条连接启用外键、忙等待和 immediate 写事务。
- 前端取消失效请求、清空旧选择、起止时间共同标识时段；认证跟随路由。
- 使用现有 Go 与 Node 内置测试器，增加统一验证脚本。

## Risks / Trade-offs

可用时段为快照，以提交事务结果为准；SQLite 写事务等待适用于当前单店规模。
仅对发现的问题实施优化，不声称所有潜在缺陷已消除。

## Migration Plan

无数据库迁移，常规构建与重启即可。测试使用临时库。
