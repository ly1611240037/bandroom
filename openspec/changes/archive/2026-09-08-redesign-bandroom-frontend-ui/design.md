## Context

当前 React 前端主要由一个 `App.jsx` 和一套全局样式承载认证、顾客预约和老板管理功能。后端 API、SQLite 数据和业务规则已经存在，本次设计需要在不改变这些接口和规则的前提下，重组前端页面。

## Goals / Non-Goals

**Goals:**

- 建立认证布局、顾客布局和老板布局三个清晰的前端区域。
- 使用路由表达页面职责和用户角色，并让登录后自动进入正确区域。
- 将预约、预约历史、通知和老板管理功能拆成易读页面。
- 统一深色音乐空间视觉、字号、间距、图标和反馈状态。
- 保证桌面演示体验，并兼容手机窄屏。

**Non-Goals:**

- 不修改 Go API、数据库表、预约规则、会员卡规则或设备库存规则。
- 不在本次变更中增加在线支付、邮件服务或新的业务流程。
- 不重做后端权限模型；前端路由保护必须与现有后端鉴权配合，而不是替代后端鉴权。

## Decisions

### 1. 使用客户端路由表达页面边界

采用 React Router，将认证页、顾客页和老板页映射到清晰 URL。相比继续在单个组件中用状态切换，路由可以支持浏览器前进后退、刷新后恢复页面和直接演示指定页面。

### 2. 使用三类布局组件

采用 `AuthLayout`、`CustomerLayout` 和 `OwnerLayout`。顾客和老板布局共享品牌、用户信息、通知入口和移动端菜单行为，但分别配置导航项和权限边界，避免把两种角色的内容混在一起。

### 3. 页面组件按业务职责拆分

将页面拆分为认证页面、顾客页面和老板页面；将预约摘要、预约卡片、统计卡片、管理列表、表单和提示消息拆为可复用组件。这样可以让 `App.jsx` 只负责路由和全局会话状态。

### 4. 采用 CSS 变量和统一设计令牌

继续使用深色背景和橙色强调色，但将颜色、字号、圆角、间距、阴影和断点集中为 CSS 变量。正文和表单文字不得继续依赖大量 10px/11px 的紧凑字号；窄屏通过布局重排而不是缩小所有文字解决空间问题。

### 5. 引入统一图标和反馈组件

使用 `lucide-react` 提供线性功能图标，使用统一的 Toast/Inline feedback 组件处理成功、失败和加载状态。取消预约、停用设备和停用会员方案等破坏性操作使用确认对话框。

### 6. 复用现有 API 数据流

保留当前 `fetch` 请求和后端 API 路径，先抽出前端 API 客户端与会话加载逻辑，再让页面组件按需请求数据。若接口返回错误，页面将错误转成用户可理解的提示，不在本次变更中改变服务端错误格式。

## Risks / Trade-offs

- [路由重构可能破坏现有验证链接] -> 保留 `/verify-email` 和 `/reset-password` 的特殊路由，并为其增加回归检查。
- [一次拆分过多组件可能增加初学者理解成本] -> 先按页面和布局拆分，复用组件只抽取有明确重复行为的部分。
- [新增依赖增加安装步骤] -> 仅增加成熟且用途明确的路由和图标依赖，并验证 `npm install`、`npm run build` 和演示启动脚本。
- [移动端内容仍可能过长] -> 使用可折叠侧边栏、单列卡片和预约摘要重排，并进行窄屏构建后的手动检查。
- [前端权限不能替代后端权限] -> 所有敏感操作继续依赖后端鉴权和角色校验，前端只负责导航和用户体验。

## Migration Plan

1. 安装并锁定前端路由和图标依赖。
2. 先建立布局、路由和会话保护，再逐页迁移现有功能。
3. 迁移完成后删除旧的单页组合布局，保留 API 调用行为。
4. 运行前端构建、Go 测试和演示启动脚本，检查登录、角色分流、预约和老板管理流程。
5. 如迁移中出现问题，可回退前端提交；后端接口和数据库无需回滚。
