## Why

当前登录页、顾客功能和老板管理功能集中在同一个页面布局中，随着功能增加，页面内容拥挤、字体偏小，用户难以理解当前所在位置。此次重构将前端组织为清晰的登录页、顾客端和老板后台，提升项目的可用性、演示效果和后续维护性。

## What Changes

- 将登录、注册和找回密码整理为独立的简洁认证页面。
- 引入 React Router，根据用户角色自动进入顾客端或老板后台。
- 为顾客端增加独立的场馆首页、预约排练、我的预约、会员卡和通知页面。
- 为老板端增加独立的数据概览、预约管理、排练房、设备、会员卡和场馆设置页面。
- 使用侧边栏导航和内容区布局，移动端支持收起侧边栏。
- 保留深色音乐空间视觉方向，重新调整字号、间距、卡片和表单层级。
- 使用 `lucide-react` 提供统一的线性功能图标。
- 增加预约摘要、分组预约卡片、统一操作提示和重要操作二次确认。
- 保留现有后端接口、业务规则和数据模型，不改变预约及会员业务逻辑。

## Capabilities

### New Capabilities

- `frontend-navigation-and-layout`: 提供按角色分流的登录、顾客端和老板后台页面结构及响应式导航。
- `frontend-booking-and-dashboard-experience`: 提供分区式预约、预约摘要、预约记录分组和老板数据概览的界面行为。

### Modified Capabilities

无。当前 `openspec/specs/` 中没有可修改的现有主规格；本次变更主要新增前端界面行为规格。

## Impact

- 主要影响 `frontend/src/` 的页面组件、路由、布局、样式和交互反馈。
- 可能新增 `react-router-dom` 与 `lucide-react` 前端依赖。
- 不修改 Go 后端 API、SQLite 数据库结构或业务规则。
- 需要更新前端构建、响应式检查和演示流程相关测试或文档。
