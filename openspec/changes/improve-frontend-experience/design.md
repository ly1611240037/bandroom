## Context

沿用 React + Go + SQLite，房间接口已提供 fixedEquipment，无需引入额外资源服务。

## Goals / Non-Goals

目标：让用户清楚选择时间、理解房间资源、读取预约记录，并覆盖已有缺陷。
非目标：真实门店资料、写实照片、交互式 3D、支付及预约业务规则调整。

## Decisions

- 同时筛选时长与开始时间范围；默认选择存在选项的分组，不删除合法时段。
- 状态以接口为准，不在浏览器将已确认记录伪造为已完成；以 UTC+8 格式化时间。前台定期刷新记录以显示后台完成结果。
- 状态徽标不参与卡片纵向拉伸。通知两个分组分别提供提示，读取失败不可伪装成无通知。
- 演示房间延用 A/B/C 名称，补充用途和设备，通过数据驱动的 SVG 等距立体示意表达站位，不声称实景或精确比例。
- seed 对相同设备使用存在性检查；只有仍为旧默认描述的房间才升级描述，用户自定义资料不覆盖。
- 登录目标限定为对应角色站内路径；手机号自动填充不覆盖已编辑值。
- 首页以接口房间容量、名称及固定设备资料在浏览器筛选；只筛选可用设备名称，维护设备不作为匹配能力；公共设备不截断为前四项。
- 通知刷新使用可取消请求，读写互斥，失败保留已加载记录并提供重试；通知时间显式按 UTC+8 显示。
- 新增 PATCH /api/notifications/read-all，接收已加载通知最大 ID throughId，服务端按会话用户及该上限更新未读记录，保留后来到达的消息和已有阅读时间。
- JSON API 成功响应解析失败或返回非对象时抛出明确异常；204 允许空响应，HTTP 失败保持状态码，取消请求仍作为取消传播。

## Risks / Trade-offs

示意图用于说明设备分区，真实尺寸、声学效果不在范围内；公共设备数量仍在提交事务中验证。页面记录状态刷新存在短暂间隔。

## Validation

运行项目检查、OpenSpec strict；浏览器验证时段与清除选择、认证返回、历史中文状态及时区、通知空态和移动端；seed 重复执行无重复设备且不覆盖自定义资料。

2026-09-10：按用户要求将布局升级为带地板、吸音墙板与设备体积的等距立体示意。设备编号对应明细，保持数据驱动，无 WebGL 依赖；可展开查看，不提供旋转漫游。
