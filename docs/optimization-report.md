# 项目检查与优化记录（2026-09-08）

## 范围与依据

检查了 React 页面与请求层、Go 认证/预约/会员/房间设备/通知/管理服务、SQLite 初始化、启动脚本及项目文档。
依据历史 OpenSpec 预约与前端规格，按 Karpathy 四项原则修复有证据的问题。
没有改变技术栈、页面设计、业务范围或老板例外调整权限。

## 已落地

| 问题 | 处理 |
| --- | --- |
| 没有统一项目开发规则 | 固定版本 skill，AGENTS.md/CLAUDE.md/OpenSpec 接入并记录来源 |
| 固定预约日期过期，测试缓存掩盖失败 | 预约服务内部测试时钟；统一检查强制无缓存执行 |
| 候选时段逐一查询房间冲突 | 批量读取当日占用区间，正常营业日共四次查询，候选在内存计算 |
| 维护房间仍返回空闲时段 | 查询房间状态，不可预约时返回空列表 |
| 时间偏移影响营业判断和老板日期筛选 | 统一按 UTC+8 校验对齐、营业时间与日期筛选 |
| SQLite 外键只在初始连接开启 | DSN 对每条连接启用外键、5 秒忙等待和 immediate 事务 |
| 同起点不同时长共用 key，切换条件残留选择 | 起止时间共同标识；切换日期/房间清空；取消过期请求；成功后刷新 |
| 认证表单与浏览器历史不同步，重置链接未填令牌 | 表单由当前路由决定，读取链接令牌，保留注册/重置成功提示 |
| 自定义请求头覆盖 JSON 头 | 使用 Headers 合并，并保留显式类型、凭据和取消信号 |
| 多处失败被吞掉，重复提交无保护 | 共用反馈 hook，老板操作、顾客取消/通知及退出显示结果并防重入 |
| 构建失败仍启动、文档路径失效 | 启动脚本失败即停、恢复环境；增加检查入口并修正文档 |
